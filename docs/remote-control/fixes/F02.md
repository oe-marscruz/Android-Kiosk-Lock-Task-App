# F02: Kiosk navigation boundary

**Replaces/amends:** §2.2 isolation bullet; §4 `op` allowlist bullet; §5.7.

## Drop-in replacement text

### §2.2 — replace the Isolation bullet
- **Isolation and navigation:** staff SSO never runs on the tablet. `MainActivity` retains the student WebView and the existing `ALLOWED_DOMAINS` (`ucdenver.edu`, `cm.maxient.com`, including label-bounded subdomains). The agent has no student-accessible UI. Remote navigation targets only this WebView, never Chrome or an intent. Resolve a fixed destination ID on the tablet and validate the resulting HTTPS URI before any app-initiated load; reject unknown IDs and malformed or non-allowlisted URIs. The initial destination is `equity_home` = the existing `START_URL`. Do not accept URLs, paths, query strings or fragments from the command.
- Use one canonical host policy for app-initiated loads and the navigation callback: require HTTPS, a valid host, no userinfo, and exact domain or dot-delimited subdomain matching after case normalization. Preserve the existing student error/retry and blank-page handling as explicit internal operations, not remote destinations. Keep student flows working; do not expand the domain list. The callback is not a complete confinement boundary: Android documents that it is not invoked for app-initiated loads or POSTs, and interception does not see subsequent redirect URLs. Do not claim POST/redirect confinement from either callback alone. [Android WebViewClient](https://developer.android.com/reference/android/webkit/WebViewClient)
- Before release, inventory and exercise the actual student pages, forms and redirects. Enforce form destinations and redirect targets at a trusted, controlled web boundary (for example, server-delivered CSP `form-action` plus controlled redirect responses), including each allowed origin that serves forms. If that boundary cannot be controlled and proven, mark WebView confinement unverified and block remote-control release; do not silently break student flows or assert client callbacks prevent POST exfiltration. Callback checks remain defense in depth.

### §4 — replace the `op` allowlist bullet
- `op` is an allowlist: `tap{x,y}`, `swipe{x1,y1,x2,y2,ms}`, `long_press{x,y}`, `key{BACK|HOME|RECENTS}`, `reload_kiosk`, `navigate{destination_id}`, `lock_now`, `reboot`, `exit_kiosk`, `enter_kiosk`, `wipe`. `navigate` accepts only the exact ID `equity_home` in v1; the tablet validates and loads its locally compiled destination. Reject unknown IDs, extra fields and URL-like values with a negative ack; do not reinterpret them. `reload_kiosk` reloads the current kiosk page without accepting a destination. Authorization and kiosk-focus requirements apply before dispatch.

### §5.7 — replace item 7
7. **Network security:** relay traffic is HTTPS/WSS only; its host is not added to the WebView allowlist. The current manifest sets `usesCleartextTraffic=true`. Inventory actual student flows before changing it. Target a network security config with cleartext denied by default and no exceptions; if a necessary existing student flow requires HTTP, document the exact host and rationale, narrowly scope any exception, and test it before release. Do not grant a relay exception or broaden navigation destinations. Network security config governs network cleartext, not WebView navigation authorization; verify the effective policy on the target build and WebView. [Android network security configuration](https://developer.android.com/privacy-and-security/security-config)

## Acceptance tests
- Unit: `navigate` maps only `equity_home` to the exact existing HTTPS start URL; unknown IDs, URLs, paths, extra fields, userinfo, scheme changes, lookalike suffixes and malformed hosts fail before `loadUrl`. Exact domains and proper subdomains pass; mixed-case host normalization is covered. Verify no intent or Chrome launch.
- API 35 emulator with controlled HTTPS test origins and request logs: exercise allowed and disallowed GET links, app-initiated loads, 301/302/307/308 redirect chains and forms using POST, including POST-to-redirect chains. Assert prohibited destinations receive no request or form body, not merely that the final page is hidden. Verify the deployed server policy on every form-serving allowed origin; demonstrate a deliberately disallowed POST is blocked. If this cannot be proven, fail the release gate.
- On K11: walk existing Equity and Maxient student links, form submission, redirects, retry, dark mode and internal blank-page behavior; compare with the current build. Capture network evidence for HTTP dependencies; verify cleartext denial and every documented exception without breaking those flows. Confirm relay WSS connects without adding its host to `ALLOWED_DOMAINS`.

## Interfaces touched
- Protocol: replace `set_url{path}` with `navigate{destination_id}`; `equity_home` is the only v1 ID. Coordinate the op list with the input-boundary and authorization fixes.
- Android: `MainActivity`, `START_URL`, `ALLOWED_DOMAINS`, shared URI policy, manifest `usesCleartextTraffic` and network security config. Trusted student web origins must supply and maintain form/redirect policy.

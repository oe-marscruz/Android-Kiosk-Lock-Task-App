# I04: fence frames through publication

**Replaces/amends:** ARCHITECTURE.md v0.4 §§2.2 (Kiosk boundary and capture: Event counter, Callback, Ring and Invalidation), 2.3 (`kiosk_remote/viewer.py` display boundary), 4 (Frames and Coordinate commands/display ack), 5.1 (Screen view).

## Drop-in Markdown

- **Tablet publication fence.** Process a screenshot in this order: callback → under the invalidation serialization validate the complete request snapshot and live boundary → drop unless `0 ≤ uptimeMillis() − request_uptime_ms ≤ FRAME_MAX_AGE_MS` → crop and encode → under that same serialization recheck the complete snapshot, event counter, live boundary, lease, grant and age immediately before writing the encoded frame to the WSS socket → write while holding the serialization. Bound the write; failure or timeout discards the frame and fails closed. Any invalidation during encoding discards the result. Only a frame passing the final check may enter the ring or be written; ring insertion and write are ordered with invalidation. Close the screenshot buffer on every callback success path, including drops and errors. `capture_uptime_ms` remains `request_uptime_ms`; never use the result timestamp for safety or age.
- **Relay and desktop fence.** The relay accepts and forwards frames only for the current live kiosk attachment and grant, including at its serialized socket writer immediately before the bounded send. Purge queued frames on invalidation. The desktop accepts a frame only for its current live attachment and grant; recheck on the Tk thread immediately before display commit and before enabling input. Released, stale, expired, replaced or invalidated IDs cannot be revived by a late frame. Invalidation clears the display reference and disables input, including when decode or display is pending.
- **Display acknowledgements.** The relay forwards `frame_displayed` only while its attachment and grant are current and live, checking again at the serialized writer. The tablet accepts it only under the invalidation serialization for the current live attachment and grant and a current ring frame. After invalidation, late acks are rejected or ignored and never establish or restore a display reference. Existing older/unknown-frame rollback protection still applies.

## Acceptance tests:

- Delay a valid callback beyond the maximum age; test both age boundaries using request uptime, and verify no crop, encode, ring insertion or write for an expired callback.
- Pause encoding, trigger each capture invalidation including change-and-return, then resume: no ring insertion or socket write occurs; the buffer is closed. An unchanged live snapshot publishes successfully. Race final check/write against invalidation and verify their serialized order; test write failure and timeout.
- Delay a frame at the relay queue and at desktop decode/Tk commit across detach, expiry, Stop and replacement attachment or grant. It is neither forwarded nor displayed, and input stays disabled. A fresh live frame still displays normally.
- Delay a display ack at the relay and tablet across the same invalidations; it cannot be forwarded or restore either reference. Older and unknown acks cannot roll back a valid reference.

## Interfaces touched:

Tablet capture callback, event serialization, frame ring and WSS writer; relay frame and ack admission and socket writer; desktop client and Tk viewer. Coordinate with I02 writer commit, I03 terminal messages, I05 enrollment and I06 publication.

# H07 — Production login gate and desktop redirect safety

**Replaces/amends:** ARCHITECTURE.md v0.3 §§2.1 (Config), 2.3 (Desktop controller), 3.1 (staff login and P5a callback origin), 3.3 (step-up), 7 (P5a/P5b).

## Drop-in amendments

### §2.1 Config — add
- `DEPLOYMENT_MODE` is required: `trial` or `production`. `STAFF_LOGIN_ENABLED=false` by default. Unknown values fail startup.
- Trial login is permitted only in `trial` mode with the explicitly configured trial issuer and RP. Trial configuration, issuer and trust bundle are rejected by production; a public P5a callback does not make it production. Production accepts only the configured CU issuer and RP.
- In production, enabling `STAFF_LOGIN_ENABLED` requires recorded, approved P5b evidence bound to the exact CU issuer, RP/client, effective base RP policy and `OIDC_REQUIRED_AMR` set. Evidence identifies the policy and its scope, the observed and accepted `amr` values and their MFA meaning, and negative tests showing bypass and skipped MFA cannot yield a staff session. A successful login alone is not evidence of MFA. Missing, stale, mismatched or inconclusive evidence keeps the gate off. Changes to those inputs or effective policy invalidate the evidence and disable login until reverified. Invalid enabled configuration fails startup.
- When the gate is off, deny staff transaction creation, start, continuation, callback and handoff redemption; issue no staff session. Deny authentication and authorization of existing staff sessions, close staff sockets and release attachments under §2.1 ordering. Tablet connectivity remains independent. Recheck the gate at each staff authentication boundary.

### §2.3 Desktop controller — add to TLS/client rules
- Native HTTPS and WSS requests carrying credentials, handoff codes, verifiers or session material never follow redirects, including same-origin redirects. Treat every 3xx as a terminal error; do not retry at `Location`. Browser navigation through Duo and the relay's loopback handoff remains the separate browser protocol.
- `urllib.request` follows redirects by default. Use a dedicated opener with the verified HTTPS handler and an `HTTPRedirectHandler` subclass whose `redirect_request` raises `HTTPError`; do not use the default opener for these requests. `http.client` callers likewise reject 3xx.
- `websockets.asyncio.client.connect` follows redirects by default. For pinned websockets 17.4, set `WEBSOCKETS_MAX_REDIRECTS=1` before importing its client module, overriding inherited environment; its loop then makes one initial handshake and no redirected handshake. A zero value makes no initial attempt. Verify this behavior on every library upgrade; fail closed if it cannot be enforced.

### §3.1 Staff login — replace step 2 desktop launch bullet
- Before opening `start_url`, parse it strictly. Require HTTPS and an exact scheme, host and effective port match to the configured relay origin; reject userinfo, malformed authority, fragments, and ambiguous or invalid URLs. Require the raw path to start with `/auth/start/`; reject encoded separators or dot segments that could alter that path. On failure abort without opening a browser. Apply the same validation to step-up `start_url` (§3.3).

### §3.3 Step-up — add
- The base login gate is necessary but not sufficient for wipe or exit. Their separate gates and the proven fresh second factor, `auth_time`, confirmation and single-use requirements remain mandatory. Trial results never enable production destructive gates.

## Acceptance tests:
- Production with gate off, no evidence, incomplete evidence, a changed issuer/RP/policy/AMR set, or failing bypass or skipped-MFA tests cannot issue or use staff sessions; existing staff sockets and attachments close on gate disable. Valid, matching approved CU evidence permits base login only when explicitly enabled.
- Trial issuer with trial mode permits P5a login; trial issuer, config or trust bundle in production fails startup. Public trial callback does not bypass this rule.
- Accepted base MFA cannot authorize wipe or exit without each separate gate and verified fresh-factor step-up; missing `auth_time`, remembered-factor reuse or bypass denies it.
- HTTPS and WSS test servers return 301, 302, 303, 307 and 308 to same-origin and foreign destinations. The original request fails, no destination receives a request or credential, and a normal non-redirecting connection succeeds. Test the packaged process with hostile inherited redirect settings.
- Login and step-up reject wrong scheme, host or port, userinfo, malformed URLs, encoded path escape and paths outside `/auth/start/` before browser launch; a valid relay URL launches.

# P0 review #1: GPT-6.2-sol (high), verdict FAIL

Reviewed ARCHITECTURE.md v0.1 at commit 65e93aa.

1. **blocker · §§2.2, 3.3, 4, 8. Remote input and capture lack a kiosk boundary.** The current launcher exposes Chrome and system Wi‑Fi Settings inside lock task. Limit v1 capture and input to the foreground kiosk window. Use `takeScreenshotOfWindow()` on the K11, reject stale frame coordinates, and replace global HOME and RECENTS with kiosk-scoped navigation. Render the staff banner as native, noninteractive UI with bounded plain text from the authenticated session. Require the banner to be visible before streaming. Stop capture and input on focus loss, lease expiry or disconnect. Require local support opt-in before capturing student content, and keep sensitive workflows out of shared frames.

2. **blocker · §§2.2, 4, 5.7. `set_url` can bypass the existing navigation callback.** `shouldOverrideUrlLoading()` does not run for app-initiated `loadUrl()` calls or for POST navigation. Prefer fixed destination IDs. If paths are required, resolve them against a fixed HTTPS origin, reject scheme and authority overrides, and validate the resulting URI on the tablet before loading it. Keep Chrome out of this command path. Test redirect and POST behavior before claiming WebView confinement. Define any cleartext exceptions and test them against existing student flows.

3. **blocker · §3.2. Specify enrollment without a bearer secret in an ADB broadcast.** During supervised USB setup, the tablet generates its key, registers a short-lived pending request over HTTPS, and displays its request ID and key fingerprint. The signed-in enrollment admin checks the fingerprint on the physical tablet and approves that exact request in the desktop app. The approved key is activated atomically after proof of possession. This supports existing tablets and removes the exported receiver. For WSS, the tablet signs a versioned transcript containing the relay audience, the device ID and a short-lived nonce bound to that socket. Consume it once. Handle StrongBox fallback explicitly. Revocation must close the live socket and require explicit re-enrollment.

4. **blocker · §3.1. Bind the browser and desktop transactions.** The desktop registers its port and S256 challenge by HTTPS POST and opens a short-lived opaque start URL. Use a browser-bound cookie and a CSRF-protected continuation POST, then require matching OIDC state, cookie and nonce at the callback. Build the handoff URL from the literal `127.0.0.1`, one decimal port in `1–65535`, and the fixed path `/cb`. Bind the listener before launching the browser, validate the callback path and desktop state, and redeem the code atomically. Suppress caching, referrers and credential-bearing logs. (RFC 8252 §8.3, RFC 9700)

5. **blocker · §§3.1, 3.3, 7/P5, 8. Make Duo MFA and step-up fail closed.** Pin the issuer and accepted algorithms, validate `azp` when applicable, and key principals by `(iss, sub)`. Require CU OIT to confirm the RP's MFA policy and accepted `amr` values. Use an explicitly configured identity-to-role mapping if groups are unavailable. Duo documents `max_age=0` for interactive reauthentication, but its Generic RP guide does not document `auth_time` in the returned claims. At P5, verify that the CU configuration supplies fresh authentication evidence and enforces MFA during step-up. Keep wipe and exit disabled until that is verified. After that, require a single-use grant bound to the same principal, session, device and action.

6. **blocker · §§2.1, 3.1–3.3, 4. Enforce authorization throughout the live connection.** Specify a per-operation role and device-scope matrix, including enrollment, reload, URL change and audit reads. Bind commands to an active attachment, with one controller lease per tablet. Enforce idle and absolute expiry on open sockets, and don't let heartbeats renew the idle timer. Terminate attachments on logout, revocation or role removal. Use bounded queues, deadlines and replay protection. Reject overload explicitly and discard stale commands on reconnect. Audit grants, denials, destructive intent and outcomes, without recording frames, secrets or raw URLs.

7. **blocker · §§2.2, 5.1–5.2, 5.4–5.5. Keep projection consent local and projection startup separate.** Remove accessibility-driven consent acceptance. Single-app sharing arrived in Android 14. The prominent chip and lock-screen auto-stop apply from Android 15 QPR1. `SYSTEM_INFO` controls status-bar indicators. Test consent and cancellation with the actual lock-task flags and immersive UI, including any activity-start or overlay restrictions. If the dialog fails, disable projection on that build. Declare the base `FOREGROUND_SERVICE` permission and the type-specific permissions. Boot starts only `specialUse`. Local consent starts the separate `mediaProjection` FGS before `getMediaProjection()`, with a registered stop callback and a single-use capture session.

8. **should-fix · §§2.2, 5.1, 5.3, 5.8, 6. Correct the accessibility and SDK claims.** AOSP's 333 ms interval is a throttle, so treat 2–3 fps as best effort. Declare the screenshot and gesture capabilities, handle secure-window and throttle errors, and report readiness only when the service is bound. `setPermittedAccessibilityServices()` accepts package names and does not enable services. Verify trusted installation, supervised enablement and reboot persistence on the K11. Preserve existing accessibility services and retire USB debugging after setup. API 30 is justified by display screenshots; Keystore and StrongBox predate it. If remote viewing requires window-scoped capture, gate that feature at API 34 and leave the P1 minimum SDK unchanged.

9. **should-fix · §§5.5–5.6, 6. Define boot, idle and recovery behavior.** Device Owner status gives an FGS background-start exemption. Use supported managed setup to verify any battery exemption. Test cold boot through first unlock, unplugged idle, network changes and reconnect on the K11. A WSS ping can keep an active NAT mapping alive but can't guarantee reachability through suspend. In the matrix, credit the DPC for setting lock-task packages and ADB for provisioning the owner. Specify `wipeDevice()` to factory-reset an individual tablet on API 34+. Define a bounded maintenance window with automatic re-entry for `exit_kiosk`.

10. **should-fix · §§2.1, 4, 7/P2–P5 and HANDOFF. Give the relay an integration owner and contract.** Assign ownership for `create_app`, config, migrations and deployment. P2 exposes typed staff/device authentication, authorization, revocation and audit interfaces. P3 consumes them and owns attachment state, queues and routing. Freeze the wire schema and error semantics before parallel work, then run one composed mock-IdP-to-fake-tablet test. Bind aiohttp to loopback behind Caddy, and add deployment verification for WSS, expiry and revocation. Do the physical K11 feasibility check before committing to P4 capture behavior.

11. **should-fix · §7/P1, P4, P6. Verify an in-place fleet upgrade.** The Windows build invokes a script that can generate a fresh signing key, and USB setup tries to uninstall on a signature mismatch. Preserve the deployed signer or define explicit reprovisioning. Test `install -r` on a provisioned Device Owner tablet and check that owner state, lock task and the enrolled key survive. Update the macOS build path too, or explicitly scope its artifact to the legacy build. (build-apk.sh:84, kiosk-manager.py:415)

12. **should-fix · §§2.3, 3.1, 7/P6. Set a concrete Win10 release gate.** A candidate lock is CPython 3.12 x64 with PyInstaller 6.20.0, websockets 17.4, Pillow 13.0.0 and certifi 2026.10.23; their package metadata and wheels are compatible. Verify the frozen artifact on CU's supported Win10 image and on Win11, as a standard user with no tablet attached. Bundle the certifi trust bundle, keep it updated, and keep hostname and certificate validation. Bind the loopback listener exclusively and test that login works without approving a firewall exception. Authenticode-sign and timestamp releases, then test campus policy with a fresh download, since SmartScreen can still prompt for a signed build.

Unverified: K11 behavior, CU Duo claims, and execution of the frozen Windows build.

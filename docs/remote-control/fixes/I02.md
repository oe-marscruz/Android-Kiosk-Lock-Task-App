# I02: Authorization commit at the writer

Replaces/amends: §2.1 (contracts, ordering and socket-writer fence), §3.3 (live authority, step-up dispatch and audit), §3.4 (management authorization and atomicity), §4 (admission and outbound delivery).

## Drop-in replacement Markdown

### §§2.1, 3.3 and 4 — Admission and writer commit

- **Admission.** Authenticate and validate the envelope, operation, targets, current session, role, scope, socket and attachment ownership, lease, local grant, maintenance state and policy gate as applicable. Enforce rate, queue, dedup and command deadline limits. Build trusted routing metadata under the ordering lock. For `wipe`, validate the step-up binding and apparent freshness without consuming it. Admission and enqueue confer no authority to send. `exit_kiosk` is reserved and denied; `wipe` is the only v1 step-up op.
- **Writer.** The sole socket writer uses one commit path for every scoped command, frame and event. Under the per-device ordering lock, resolve authoritative live state and rebuild the context; check session validity, current role and scope, revision, device, socket and attachment ownership, lease, local grant, maintenance, gate and deadline as applicable. A revision mismatch requires a fresh decision, not automatic permission. Then, without releasing the lock:
  1. Run final live authorization. It checks ordinary authority and the local approval grant; it does not consume or require an already-consumed step-up.
  2. For `wipe` only, call atomic `consume_step_up` once. It revalidates freshness and all step-up bindings against current state and marks the single-use ID consumed. No other path consumes it.
  3. Durably record the required intent audit before dispatch, including destructive intent for `wipe`.
  4. Perform a bounded `ws.send`, retaining the lock through completion or failure.
- Denial, expiry, unavailable state or failed consumption drops the item without sending; no step-up is consumed on a failed consumption. Audit failure prevents send; if consumption already succeeded, the step-up stays consumed. A stalled or failed send closes the socket; after send is attempted, a command without a definitive acknowledgment is `OUTCOME_UNKNOWN`, including failure after consumption and audit. Never restore the step-up or replay the command. Bytes handed to transport cannot be recalled. Report pre-send failures through the applicable terminal result; content-free cleanup uses the separate unscoped path.
- Revocation, expiry, scope changes and attachment transitions share this ordering with writers. If a mutation wins after enqueue, the writer sees it and denies or reauthorizes against the new state; if the writer wins, the mutation waits for the bounded send. Queue purge is defense in depth.

### §3.4 — Management ordering

Management authorization and mutation are one ordered operation, not a check followed by an unlocked write. Acquire the affected session and device ordering locks in a single documented deterministic order, shared by writers, policy changes, expiry and revocations; then resolve current state, build `HttpMgmtContext`, authorize, and commit mutation and required audit atomically before releasing locks. Reassignment checks both current and destination groups. Session revocation locks the actor and target sessions and all affected devices, resolves the target's entire current scope under that ordering, and requires authority over all of it. Coordinate changes to that scope with the same ordering; retry lock acquisition if the affected set changes. Device-less management uses the relevant session/global ordering and its explicit scope rules. Unavailable state or audit failure denies and rolls back; cleanup and revision publication follow §2.1 before success.

## Acceptance tests:

1. Barrier after enqueue and before writer lock: independently revoke session/device, remove or reassign scope, and expire session, lease or local grant. For commands, frames and scoped events, assert no unauthorized bytes; repeat for queued `wipe`, including expired or revoked step-up, and assert no consumption. Reverse the race: mutation waits for bounded send.
2. Exercise the single writer path: successful `wipe` consumes exactly once before durable audit and send; duplicate/replay cannot consume again. Inject authorization, consume and audit failures; assert no send, and that a successful consume survives audit failure. Fail or stall send after audit: socket closes, result is `OUTCOME_UNKNOWN`, and consumed ID remains unusable.
3. Barrier before management lock acquisition: revoke the actor, change its scope or expire it; assert mutation and success are denied. Change target-session scope after request admission, including adding an out-of-scope device; session revoke must deny. Reverse each race and assert ordering, atomic audit/rollback and cleanup before success. Include enrollment assignment and approval with expiry and concurrent scope changes.

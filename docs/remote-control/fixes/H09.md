### §2.3 — Packaging
- CPython **3.14.10 x64**, PyInstaller 6.20.0, websockets 17.4, Pillow 13.0.0 and certifi 2026.10.23. Python 3.12 is in source-only security maintenance; 3.12.10 was its last binary installer and lacks later security fixes. Python 3.14 has Windows 10 support and PyInstaller 6.20 supports Python 3.14. Verify the complete locked dependency set and packaged executable on both acceptance images before release.
- Bundle Android SDK Platform-Tools **37.0.3**, fetched from `https://dl.google.com/android/repository/platform-tools_r37.0.3-win.zip`; SHA-256 `89d108360a3bf2924d3bea837239edaccc22fd6ff5befd3787c4348a9fe4f09d`. Verify the digest before extraction; mismatch fails the build. Do not use `platform-tools-latest`. Google publishes this versioned archive in its SDK repository metadata.
- `requirements-win.lock` pins every package with a hash, installed with `--require-hashes --only-binary=:all:`. The certifi `cacert.pem` is bundled.
- The release is Authenticode-signed with SHA-256 and an RFC 3161 timestamp, then checked with `signtool verify /pa /all`.
- Staff are never told to bypass SmartScreen.

### §7.3 — Windows release gate (P6)
- CU IT supplies and maintains two representative x64 acceptance images, named `CU-WIN10-<build>` and `CU-WIN11-<build>`. Each record contains the exact OS build and edition, default browser and version, proxy/PAC configuration, endpoint/AV policy and standard-user status. Record actual values, not placeholders; changes require a new record and rerun. Both records and passing evidence are required for release.
- On each image, as a standard user without admin rights or Python installed, freshly download the same final signed candidate. Verify SHA-256 against the candidate hash and run `signtool verify /pa /all`. Record SmartScreen and Defender results. Start with no tablet attached to the PC.
- Against staging and an enrolled test tablet, use an in-scope operator: log in, list the tablet, request a kiosk attachment, obtain local approval on the tablet, display a frame, tap a safe test target, detach and log out. Confirm the tap's visible result and attachment termination. Apply the normal banner, grant and boundary rules; no unattended approval.
- Also run login, logout, login again, cancel and timeout; confirm the listener closes each time. The listener must be on `127.0.0.1` only; a competing bind must fail and it must not be reachable remotely.
- TLS: a valid certificate succeeds over HTTPS and WSS. An untrusted, expired or hostname-mismatched certificate fails over both, using the isolated test bundle against the packaged exe.
- The gate fails on any inbound firewall prompt or rule change, UAC prompt, or SmartScreen block that stops normal use.
- Record for each image: image record, date, tester, commit, final candidate SHA-256, signature result, staging configuration, test tablet/build, each step and observed outcome, SmartScreen/Defender results, and links to sanitized evidence. Failures and reruns remain in the record. Never record credentials, tokens or sensitive frames. Evidence is valid only for the exact candidate hash and image configuration.

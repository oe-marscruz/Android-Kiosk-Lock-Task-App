# J02 — Wipe writer and result transitions

Replaces/amends: ARCHITECTURE.md v0.5 §2.1 “Admission vs. writer commit”; §3.3 “Step-up for wipe” (Dispatch); §4 “Relay → device”, “Terminal results”, “Wipe reservation”, “Admission” and “Errors”.

## Drop-in Markdown

For one `(attachment_id, command_id)` wipe, use the following transitions. “Audit” means the durable destructive intent audit; other security events retain §3.3 audit requirements. All relay writer checks and sends hold the §2.1 device ordering lock. A pre-send terminal failure is never `OUTCOME_UNKNOWN`.

| Transition | Writer check | Consume step-up | Mark dispatch | Intent audit | Deadline recheck |
|---|---|---|---|---|---|
| admitted → reserve_sent | Rebuild live context; check session, role, scope, device/socket/attachment, lease, grant, maintenance and gate | No | No | No | Check command deadline immediately before send; positive `ttl_ms` and send timeout ≤ remaining budget |
| reserve_sent → reserved | Match authenticated connection, both IDs and reservation to pending command | No | No | No | Reject a response at or after relay command deadline |
| reserved → execute_committing | Under writer lock repeat live checks; require matching reservation and atomically validate and consume bound step-up | Yes, once | No | No | Check all applicable time-based authority and relay command deadlines before consumption |
| execute_committing → execute_sent | After successful durable intent audit, recheck time-based session, lease, grant and command deadlines; if any expired, stop | Already consumed | Register correlation before attempting send | Yes, before recheck | Recheck after audit; send timeout ≤ remaining applicable relay deadline budget; no send if nonpositive |
| execute_sent → terminal | Match ack to original authenticated device connection and both IDs | No | Already registered | Record outcome | Tablet checks its own reservation expiry immediately before dispatch |
| admitted, reserve_sent, reserved or execute_committing → terminal | Denial, expiry, disconnect, failed consumption or audit prevents execute | Only if consumption already succeeded; never restore | No | Record intent only if audit succeeded | Expiry gives `rejected_expired`; other failures give `failed` |

`execute_sent` means an execute send was **attempted**, including a failed or stalled send. Register correlation against the original authenticated connection and both IDs immediately before the attempt; close the socket on a failed or stalled send. A definitive ack maps success to `ok`, `RESERVATION_EXPIRED` to `rejected_expired`, and other negative acks to `failed`. Only an execute attempt without a definitive ack yields `outcome_unknown` (`OUTCOME_UNKNOWN`); never replay. Audit failure or post-audit expiry prevents the attempt even though the step-up remains consumed.

Relay must reject any attempt to emit plain `cmd{op:"wipe"}`; tablet must reject such a message without dispatch. Staff still requests wipe through `cmd`. Relay sends `reserve{command_id, op:"wipe", attachment_id, ttl_ms}` and `execute{reservation_id, command_id, attachment_id}`. The tablet binds and verifies all three execute fields against the reservation and authenticated connection. The IDs on execute also allow a negative response when the reservation is unknown. At or after expiry, or if unknown, the tablet sends unsolicited `ack{command_id, attachment_id, ok:false, err:"RESERVATION_EXPIRED"}` without invoking wipe. An ID mismatch never dispatches. Release, disconnect, restart or invalidation destroys unused reservations; duplicate execute never dispatches again.

A matching late ack from the original authenticated connection after `OUTCOME_UNKNOWN` only reconciles the audit record; it does not change the reported terminal result, restore authority or forward content to a replacement attachment. Retain correlation and dedup tombstones for `ACK_RESULT_WINDOW_S`; discard later or mismatched acks.

Add `RESERVATION_EXPIRED` to §4's admission and delivery error registry. It is valid as the negative ack `err` as well as a reported command error.

## Acceptance tests:

- Pause the intent audit after consumption, advance each applicable relay deadline past expiry, then release the audit: assert no execute attempt, no dispatch correlation, expired terminal result and consumed step-up. With time remaining, assert correlation precedes send and its timeout is capped by the remaining budget.
- Release between reserve and execute: assert no execute, no consumption and no wipe. Separately deliver execute after tablet expiry or reservation destruction: assert the negative ack retains both IDs and no wipe. Reject plain wipe `cmd` on relay and tablet; duplicate execute cannot wipe twice.
- Attempt execute, withhold ack until `OUTCOME_UNKNOWN`, then send a matching ack on the original authenticated connection: only audit changes. Wrong connection or either wrong ID cannot reconcile. Verify pre-attempt failures never report `OUTCOME_UNKNOWN` and a definitive negative ack reports `rejected_expired`.

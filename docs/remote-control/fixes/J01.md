**§2.2, after lock-task ownership:**
- **Supervised USB exit and re-entry.** Keep a person at the tablet throughout. Connect an authorized USB debugging host and select the intended device. Run `exit-kiosk.bat` or the manager's Exit Kiosk action: both force-stop `com.example.webkiosk`; neither writes a maintenance marker. Check the command result and verify the global lock-task state is `NONE` before maintenance. A force-stop or a success message alone is not proof of exit. If it fails, stop and investigate locally.
- If needed, the manager's Restore All Apps action enumerates disabled packages and enables them; it is separate from exit and can affect other disabled apps. Do not use it indiscriminately. Neither exit nor restore removes Device Owner. Do not follow the scripts' Device Admin deactivation suggestion as an exit step.
- After maintenance, unlock the keyguard and launch HOME explicitly: `adb -s <serial> shell am start -a android.intent.action.MAIN -c android.intent.category.HOME -n com.example.webkiosk/com.example.kiosklauncher.LauncherActivity`. HOME launches `MainActivity` via the §2.2 controlled transition. Verify `LOCK_TASK_MODE_LOCKED`, the same resumed root and task ID, and the persisted identity against `getAppTasks()`; confirm `status.owner_verified` is `true`. A global `LOCKED` alone is insufficient. If any check fails, keep the tablet supervised and report recovery failure; do not claim successful re-entry.

**§7.1, replace Upgrade acceptance (K11):**
1. Record device, installed version and signer, Device Owner, allowlist, task identity and device-key fingerprint.
2. With the matching signer, `adb install -r` a higher version on a locked tablet. Reboot; verify owner and allowlist unchanged, controlled ownership re-established, `LOCKED` and `status.owner_verified=true`. Verify the same device key signs a fresh challenge.
3. On a separate baseline or reset fixture, perform supervised USB exit above, verify `NONE`, then install the higher version with `install -r` while locally exited. Reboot and perform the supervised re-entry and ownership checks above. Verify owner, allowlist and device key as in step 2. Record each result; do not assert a maintenance marker was cancelled.
4. Attempt an incompatibly signed upgrade and confirm failure without uninstalling. Record evidence for both upgrade paths.

**§9, v0.5 note:** Replace the claim that `enter_kiosk` is kept with: `enter_kiosk` is reserved and denied in v1; re-entry is supervised over USB (§2.2).

**Script changes (spec only):**
- `exit-kiosk.bat`: select one authorized device, check ADB and force-stop failures, verify `NONE`, and report failure rather than unconditional success. Remove the Device Admin deactivation advice. Provide the supervised re-entry command and verification instructions; never claim success from launch alone.
- `kiosk-manager.py`: apply the same device selection, exit checks, failure reporting and re-entry guidance. For Restore All Apps, report enumeration and per-package failures accurately and warn that it enables all disabled packages; do not claim the drawer is fully restored without verification. Remove the Device Admin deactivation advice.

## Acceptance tests

- Both reserved operations are denied for every role, attachment, grant, policy and configuration at relay and tablet; no command is executed.
- On K11, both §7.1 upgrade paths pass with recorded `NONE` after USB exit and `LOCKED`, verified owner identity and `status.owner_verified=true` after re-entry. Key challenge and signer mismatch checks pass.
- Force-stop failure, missing or ambiguous device, `PINNED`, pre-existing `LOCKED`, duplicate or unknown root, failed launch and failed ownership verification never report success. Restore failures are reported.

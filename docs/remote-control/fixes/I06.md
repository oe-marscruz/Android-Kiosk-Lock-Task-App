# I06: Default-deny publication

Replaces/amends: ARCHITECTURE.md v0.4 §§7.2 (publication matrix, legacy retirement and Windows verification), 7.3 (signature evidence), 8.2 (internal distribution).

## Drop-in Markdown

### §7.2: Publication authorization

Classification and all existing package, APK, signer and candidate-bound remote gates must pass before publication. Class means capability (`usb` or `remote`), APK (`debug` or `release`), and, for Windows, EXE (`unsigned` or `signed`). Signed means verified below. Unknown, inconsistent or failed classification is denied. The only allowed mutations are:

| Event and ref | Windows class | Windows mutation | macOS class | macOS mutation |
|---|---|---|---|---|
| `push` to repository default branch | usb / debug / unsigned | Restricted internal upload | usb / debug | Restricted internal upload |
| `push` to repository default branch | usb / release / signed | Labelled public prerelease, never `latest` | usb / release | Restricted internal upload |
| `push` to repository default branch | any other | Deny | remote / release | Restricted internal upload |
| `push` of `refs/tags/v*` | usb / release / signed | Labelled versioned release | usb / debug, usb / release, remote / release | Restricted internal upload |
| `push` of `refs/tags/v*` | remote / release / signed, with all remote gates | Labelled versioned release, never `latest` | any other | Deny |
| `push` of `refs/tags/v*` | any other | Deny | — | — |
| `pull_request`, any ref | any | Deny | any | Deny |
| `workflow_dispatch`, any ref | any | Deny | any | Deny |
| Any other event or ref | any | Deny | any | Deny |

Deny includes every `actions/upload-artifact` invocation, other uploads, release creation, editing and asset deletion. No implicit fallback or diagnostic artifact upload. A public repository's Actions artifacts are not private. Internal upload requires a configured `PRIVATE_ARTIFACT_DESTINATION` pointing to an independently access-restricted private destination; unset, invalid, inaccessible or unverified destination means no upload. A private-repository Actions artifact is allowed only when its repository and access restrictions are verified; do not upload internal artifacts to this public repository. Keep the §8.2 warning with internal debug artifacts.

Use a `classify` job after building and verifying the final candidate; emit explicit allow outputs only after all checks pass, otherwise emit none or `false`. Every publishing job directly `needs: classify`, requires its success, and every upload or release mutation step checks its specific allow output **and** the event and exact ref. For example, a default-branch prerelease step uses:

```yaml
if: ${{ needs.classify.result == 'success' && needs.classify.outputs.windows_prerelease == 'true' && github.event_name == 'push' && github.ref == format('refs/heads/{0}', github.event.repository.default_branch) }}
```

The tag equivalent additionally requires `startsWith(github.ref, 'refs/tags/v')`; internal steps use their own class-specific allow output and destination verification. `needs` must be a direct dependency, and the check applies to each mutation step, including post-actions or helper scripts that upload. Grant `contents: write` only to the eligible release job; PRs get no release secrets or write permission. The output authorizes the verified digest and commit only; publish those exact bytes. Missing outputs, failed or skipped jobs and all other conditions deny. GitHub supports `needs` and `github` in job and step `if` expressions.

Legacy `latest` asset retirement is a separate, explicitly authorized operation, such as a dedicated workflow protected by an environment requiring approval. Normal builds and dispatches above cannot delete or replace it. Until separately authorized, leave the existing asset and links untouched; do not claim they are a verified current release. Failed verification never mutates an existing release.

### §§7.2–7.3: Windows publisher and timestamp evidence

Sign with SHA-256 and RFC 3161 `/tr` and `/td SHA256`. On the final EXE, run `signtool verify /v /pa /all /tw`; fail on any warning or error, including warnings with exit code zero. Independently enumerate every embedded signature and require its verified signer certificate thumbprint to equal the nonempty, normalized repository variable `WINDOWS_SIGNER_THUMBPRINT`; record the subject and thumbprint. Missing pin, unmatched signer or extra unverifiable signature fails.

For each signature separately, use a version- and digest-pinned PKCS#7 parser to inspect its unsigned attributes and require an RFC 3161 timestamp token under OID `1.3.6.1.4.1.311.3.3.1`. Validate the token signature, timestamp authority chain and time, and message imprint against that signature's signature value; reject missing, malformed, invalid or legacy-only timestamps. SignTool's documented verbose output does not promise a stable protocol discriminator; PowerShell's `TimeStamperCertificate` identifies a certificate, not the protocol. Neither alone establishes the required type. Retain per-signature publisher, timestamp validation and parser version evidence bound to the final EXE digest; repeat on both §7.3 acceptance images. Never fall back to unsigned after signing failure.

### §8.2: Internal distribution

The unsigned USB-debug exception is available only through the verified restricted destination above, with the existing signer and supervised-recovery warning. If no destination is configured, no internal artifact is uploaded.

## Acceptance tests:

- Exercise every event/ref × class in both workflows, including non-default branch, non-`v` tag, PR, dispatch on branch and tag, and unexpected event. Assert every upload and release API mutation matches the table; failures and missing outputs produce none.
- Unset or invalidate the destination, or make it public/inaccessible: all internal uploads are suppressed. Verify authorized private access and the warning when configured.
- Normal runs leave `latest` unchanged; a separate retirement operation cannot execute before its protected-environment approval. Check deletion only after explicit authorization in a test release.
- Test correct and wrong publisher, unset pin, multiple signatures with one wrong signer, missing, invalid, legacy-only and valid RFC 3161 timestamps, and one invalid timestamp among multiple signatures. Reject warnings even with exit zero. Bind evidence to the tested EXE digest.
- Replace or alter the candidate after classification, or fail any package or remote gate: no mutation occurs. Confirm actual job output and event/ref expressions enforce the table.

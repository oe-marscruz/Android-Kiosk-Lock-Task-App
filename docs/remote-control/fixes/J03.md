# J03 — Invalidation contract

**Replaces/amends:** ARCHITECTURE.md v0.5 §§2.2 (Tablet lease: Terminal events; Kiosk boundary and capture: Invalidation), 2.3 (`kiosk_remote/viewer.py`: Display boundary), 3.3 (attachment lifecycle), 4 (message lists and relay frame fence).

## Drop-in Markdown

### Terminal reasons (§§2.2, 3.3, 4)

`support_stopped` and `attachment_ended` carry `attachment_id` and one reason from this closed registry. Text shown is a fixed local string; no page content, URL, native control text or diagnostic detail is sent or displayed.

| Reason | Origin | Desktop shows |
|---|---|---|
| `local_stop` | tablet | Support stopped locally |
| `grant_expired` | tablet or relay | Support approval expired |
| `lease_expired` | tablet or relay | Attachment expired |
| `focus_lost` | tablet | Kiosk lost focus |
| `obscured` | tablet | Kiosk obscured |
| `sensitive_state` | tablet | Kiosk unavailable for sharing |
| `geometry_changed` | tablet | Kiosk view changed |
| `banner_lost` | tablet | Support banner unavailable |
| `suspend` | tablet | Tablet suspended |
| `screen_off` | tablet | Tablet screen off |
| `service_failure` | tablet | Tablet service unavailable |
| `enrollment_opened` | tablet | Enrollment opened |
| `detached` | relay | Attachment ended |
| `disconnected` | relay | Connection lost |
| `revoked` | relay | Access revoked |
| `policy_changed` | relay | Support policy changed |

Map unknown or sensitive page state to `sensitive_state`; navigation, page/load/URL generation or geometry changes to `geometry_changed`; maintenance start to `policy_changed`. Session end or device revocation maps to `revoked`; scope, role or policy changes map to `policy_changed`. If multiple causes race, the first serialized terminal transition wins.

Tablet boundary invalidation releases locally first and sends unsolicited `support_stopped{attachment_id, reason}` for a kiosk grant; tablet lease expiry retains `attachment_expired{attachment_id, reason:"lease_expired"}` in either mode. No retry is required after disconnect. The relay validates tablet reasons against their permitted origins, applies matching events under the device lock, releases the attachment and purges scoped work, then sends `support_stopped` for a stopped kiosk grant or `attachment_ended` for other releases. Relay-detected expiry and releases use the same registry. Stale or duplicate IDs cannot affect a replacement. Unknown reasons are rejected, never rendered as arbitrary text; connection loss independently clears the viewer even if no terminal event arrives. Cleanup notifications remain content-free and bounded.

### Viewer display boundary (§§2.3, 4)

Viewer state and invalidation are serialized on the Tk thread. WSS events received on the asyncio thread enter a thread-safe queue polled by `root.after`; decoded results are marshalled the same way. For each frame:

1. On Tk, disable input.
2. Decode off the UI thread.
3. On Tk, check that the attachment and grant are current and live.
4. Commit the frame and its identity as the displayed reference.
5. Send `frame_displayed{attachment_id, grant_id, frame_id, generation}` through the WSS sender.
6. On Tk, recheck attachment and grant liveness and that the displayed reference is still this frame.
7. Only if all checks pass, enable input.

Sending is nonblocking; if it fails, invalidate the display and keep input disabled. Invalidation runs on Tk, clears the reference and disables input, and is ordered with steps 3–7. A delayed decode or continuation cannot revive an invalidated or replaced attachment or grant. The relay and tablet retain their live writer and ring checks; an ack does not itself restore authority.

## Acceptance tests:

- Exercise every registry reason, its permitted source and fixed display text; reject unknown and wrong-source tablet reasons. Verify local cleanup, matching relay release, duplicate/stale isolation, no content in notifications, and disconnect cleanup when the event is lost.
- Pause decode, invalidate on Tk, then complete decode: no commit or ack, and input remains disabled. Repeat with a replacement attachment or grant; a fresh frame can display.
- Pause after ack submission and before input enablement, process invalidation on Tk, then resume: the recheck fails, the reference remains cleared and input stays disabled. Also replace the displayed frame at that barrier; the old continuation cannot enable input. Verify the uninterrupted live sequence enables input and send failure does not.

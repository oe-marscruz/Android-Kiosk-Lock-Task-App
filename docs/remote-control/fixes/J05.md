# J05: Executable publication matrix

Replaces/amends: ARCHITECTURE.md v0.5 §§7.2 (default-deny matrix, classify job, mutation steps and legacy asset), 8.2 (internal distribution and public download).

## Drop-in Markdown

### §7.2: Publication authorization

Evaluate each platform independently after its own classification and verification. A failure or denial on one platform does not deny the other. All §7.2 classification, APK, final package and applicable Windows signature checks remain mandatory. Only the following mutations are allowed; all other classes, events and refs deny.

| Windows event and ref | Class | Allowed mutation |
|---|---|---|
| `push`, default branch | USB / debug / unsigned | Restricted internal upload |
| `push`, default branch | USB / release / signed | Labelled public prerelease |
| `push`, `refs/tags/v*` | USB / release / signed | Labelled versioned release |
| `push`, `refs/tags/v*` | remote / release / signed | Labelled versioned release, only with P0, P5b, §5.7, fleet-upgrade and §7.3 gates bound to commit and final digest |

| macOS event and ref | Class | Allowed mutation |
|---|---|---|
| `push`, default branch or `refs/tags/v*` | USB / debug or USB / release | Restricted internal upload |
| `push`, default branch or `refs/tags/v*` | remote / release | Restricted internal upload only after P0 and §5.7 pass, bound to commit and final DMG digest |

Remote macOS staging requires the classification, APK and DMG verification, approved release APK fingerprint, candidate-bound P0 and §5.7 evidence, and verified private destination. It does not require P5b, fleet-upgrade or Windows-only §7.3 for private staging; those remain requirements for the Windows remote release. No remote DMG is uploaded anywhere before P0 and §5.7 pass. No public DMG release is authorized. Remote debug is denied.

Denial includes every artifact or other upload, release creation or edit, and asset deletion, including helpers and post-actions. PRs, dispatches, unknown classes, failed or missing checks and all unlisted cases deny. Internal upload requires an independently access-restricted, verified, accessible `PRIVATE_ARTIFACT_DESTINATION`; public-repository Actions artifacts are not private. Unset or invalid destination means no upload.

**Candidate handoff.** Keep final bytes in the eligible platform job: build, sign where applicable, verify, classify and publish in that same job. Replace the cross-job `classify` output with explicit step outputs defaulting to deny. Each mutation step independently checks its own allow output, successful verification, event and exact ref; recheck the final digest immediately before mutation. No artifact upload is used as a handoff. Only an eligible release job receives `contents: write`; PRs receive no secrets or write permission. Never test secrets directly in `if:`.

**Release names.** The old workflow publishes a release tagged `latest`; normal builds must never edit, replace or delete that release or its assets. Retirement remains separately authorized. GitHub's `/releases/latest/download/<asset>` is a selector, not a reference to the tag: it selects the latest non-draft, non-prerelease release, ordinarily sorted by the release commit's `created_at` (GitHub also supports explicitly setting latest). A labelled USB prerelease cannot become latest; a published versioned `v*` release can become latest and redirect the selector, even though the legacy tag is untouched. A selected release without the named asset does not fall back to the legacy asset. See [GitHub's latest-release API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release) and [release management](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository).

### §8.2: Internal distribution and download

Every internal USB-debug artifact must carry a visible accompanying warning, delivered with the artifact: **Debug APK, not a fleet release. Each CI run may use a different signing key, so updates to existing installations can fail. Do not uninstall or reset to force an update. Inventory the installed signer and follow supervised recovery.** For Windows add: **Unsigned executable.** Retire this exception once stable signing and signed distribution exist.

The committed README badge and direct-download link point to `TriBrigadeMars/Android-Kiosk-Lock-Task-App/releases/latest/download/CU-Denver-Equity-Kiosk-Manager.exe`, not directly to the `latest` tag. Their target can change as the upstream repository's latest release changes; leaving the link text unchanged does not pin its bytes. Do not describe it as a verified current release. A decision on the legacy asset and link, and a private destination, remains open; no automatic retirement is authorized.

## Acceptance tests:

- Exercise both platform tables across default and non-default branches, `v*` and other tags, PR and dispatch, all classes and failures. Assert every actual mutation is authorized; Windows denial does not suppress eligible macOS and conversely.
- Omit or fail each P0, §5.7, verification and destination check for a remote DMG: no upload. Confirm eligible private staging needs neither Windows §7.3 nor P5b nor fleet-upgrade evidence. Verify destination access is restricted.
- Alter final bytes after verification or omit an allow output: no mutation. Confirm each mutation checks event, exact ref and digest in the same job and no handoff upload occurs.
- In a test repository, preserve the legacy `latest` tag and asset; verify a prerelease does not become latest, a qualifying versioned release can change the selector, and a missing asset fails rather than falling back. Check both README URLs against the upstream selector.
- Verify each private USB-debug artifact includes the signer and supervised-recovery warning, and Windows also identifies the unsigned executable. No private destination means no artifact.

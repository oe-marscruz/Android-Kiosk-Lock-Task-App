# F09 — Boot, idle and recovery

**Replaces/amends:** §§2.2 (first bullet), 4 (admin operation semantics), 5.5–5.6, 6 (first two capability rows).

## Drop-in text

### §2.2 — replace `RemoteAgentService` bullet

- `remote/RemoteAgentService`: a `specialUse` foreground service for one outbound WSS connection. Start after first unlock and recover as specified in §5.5–5.6. Projection uses a separate service and requires local consent.

### §4 — add after the operation list

- `wipe` requests factory reset of this tablet with `DevicePolicyManager.wipeDevice(0)` on API 34+, after the existing authorization, confirmation and fresh-auth gates. Reject on older APIs; report a request failure if the call throws. An accepted request is not proof that reset completed; audit intent before invoking it and verify reset during reprovisioning.
- `exit_kiosk` opens a fixed 10-minute maintenance window; it does not extend on disconnect or repeated requests. The kiosk activity that started lock task calls `stopLockTask()`. Persist the deadline before exit; immediately stop capture/input and report maintenance state. `enter_kiosk` closes the window early. At expiry restore the approved lock-task policy and launch the kiosk into lock task; retry on next service start if the launch fails, report failure, and require local recovery. On reboot or process restart, cancel any outstanding window and re-enter after first unlock. A clock change must not extend a window: use elapsed realtime during the boot and fail closed on restart. Never change the student WebView allowlist. [Lock task guidance](https://developer.android.com/work/dpc/dedicated-devices/lock-task-mode), [wipeDevice](https://developer.android.com/reference/android/app/admin/DevicePolicyManager#wipeDevice(int)).

### §5 — replace items 5 and 6

5. **Boot and recovery:** Register a `RECEIVE_BOOT_COMPLETED` receiver for `BOOT_COMPLETED`; use credential-encrypted state and start only the `specialUse` FGS after first unlock. Do not register `LOCKED_BOOT_COMPLETED` or promise remote control before first unlock. After boot restore kiosk policy and enter lock task; if locked at boot, local unlock is required. The device-owner DPC has a background FGS-start exemption; boot type restrictions still apply. Log and report startup failures when connectivity returns. Verify cold boot, first unlock and kiosk launch on K11; Android may delay delivery. [Direct Boot](https://developer.android.com/privacy-and-security/direct-boot), [FGS restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start).
6. **Idle and network:** During managed setup check `PowerManager.isIgnoringBatteryOptimizations(packageName)`; report the result. Use supported Settings exemption flow under supervision if needed, and verify the result; do not assume a DPM API can add arbitrary packages to the Doze allowlist. The DO may manage supported policies but exemption is not a reachability guarantee. Maintain one connection; on disconnect use exponential backoff with full jitter (1 s initial, 60 s cap), reset after a stable connection, and discard stale commands. A default-network callback triggers a fresh attempt when a usable network returns, without parallel attempts; authentication failures stop retrying until configuration or enrollment changes. A 25 s ping can preserve an active NAT mapping but cannot prevent suspend, Doze or network loss. The relay marks missed heartbeats offline; no immediate remote wake or bounded reconnect is promised. [Doze guidance](https://developer.android.com/training/monitoring-device-state/doze-standby), [PowerManager](https://developer.android.com/reference/android/os/PowerManager#isIgnoringBatteryOptimizations(java.lang.String)).

## Acceptance tests

- Unit: fake clock and policy/activity adapter: exit expires at 10 minutes, repeated exit and wall-clock changes cannot extend it; early enter, process restart, reboot and launch failure produce the specified state and retry. Capture/input stop immediately on exit.
- Unit: deterministic jitter/network events verify capped backoff, one connection attempt, reset after stability, no replay of queued commands, and authentication failure does not retry indefinitely. Mock DPM verifies `wipeDevice(0)` only after authorization and records exceptions as failure.
- API 35 emulator with provisioned DO: cold boot with secure lock, verify no agent connection before unlock; unlock and observe FGS, kiosk lock task and relay connection. Trigger exit, expiry, early enter and reboot during maintenance; verify re-entry and failure reporting. Check `isIgnoringBatteryOptimizations` against Settings and simulate network loss/restoration.
- K11 checkpoint: repeat cold boot/first unlock, maintenance expiry and reboot; unplug, idle with screen off through Doze, record offline duration and recovery after wake; switch Wi-Fi and restore network, verify reconnect without duplicate sockets. Verify kiosk re-entry with actual background activity restrictions. On a disposable provisioned tablet only, authorize wipe and confirm factory reset and enrollment loss.

## Interfaces touched

Existing `exit_kiosk`, `enter_kiosk`, `wipe`, `status` and `ack`; status must expose maintenance and recovery failure to the relay. `RemoteAgentService`, `AdminCommandHandler`, kiosk activity, boot receiver; persisted maintenance deadline and network retry state. Coordinate status schema and audit outcomes with the protocol/security owners.

# H04: bind capture to request state

**Replaces/amends:** ARCHITECTURE.md v0.3 §§2.2 (Kiosk boundary and capture), 2.3 (Display boundary), 4 (Frames, coordinate validation and display acks), 5.1 (screen view).

## Drop-in replacement

- **Capture request.** Before `takeScreenshotOfWindow`, under the same serialization as invalidation, verify the live grant, attachment, foreground window, banner, geometry and shareable state. Record `{request_uptime_ms, grant_id, attachment_id, window_id, generation, shareable_page_generation, event_counter}`. `request_uptime_ms` is tablet `SystemClock.uptimeMillis()`. The shareable-page generation increments on every WebView navigation, page load, URL change or sensitive-state change, even if the old state returns. Unknown or unobservable state fails closed.
- **Events and callback.** A monotonic event counter increments on navigation, page load, URL change, sensitive-state change, obscuration, Stop, suspend, screen-off and every other grant or geometry invalidation. Serialize the event updates, request snapshot, callback validation, ring insertion and invalidation; no event may cross validation and publication. On callback, revalidate the live boundary and shareable state and require every recorded identity, generation and counter to match current state. Any intervening event, missing state or mismatch drops the result before encoding, retention or sending. Close the `HardwareBuffer` on every success callback, including every drop and failure path, after any permitted use. If event observation or ordering cannot be established, capture fails closed.
- **Frame ring and display.** Retain only validated frames, with `capture_uptime_ms = request_uptime_ms` and the existing frame identity, geometry and exclusions. Use this conservative time for the existing `0 ≤ uptimeMillis() − capture_uptime_ms ≤ FRAME_MAX_AGE_MS` check; reject an already expired result. Never use `ScreenshotResult.getTimestamp()` for safety or age. Clearing the ring also clears the tablet's latest accepted desktop display reference; invalidate the desktop's displayed reference and disable input on the same invalidation, detach, disconnect or expiry. Delayed frames and acknowledgements cannot restore a cleared reference.
- **Clock and source.** Suspend and screen-off invalidate the grant and pending captures; uptime excludes sleep. Android documents `getTimestamp()` as non-sleep uptime. In [Android 15 AOSP](https://android.googlesource.com/platform/frameworks/base/+/android-15.0.0_r1/core/java/android/view/accessibility/AccessibilityInteractionClient.java), `setTakeScreenshotOfWindowResult` constructs the result with `uptimeMillis()` when the result callback arrives, before scheduling `onSuccess`; it does not establish when pixels became safe. See [ScreenshotResult](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService.ScreenshotResult).

## Acceptance tests:

- Delay a callback across navigation, page load, URL change and sensitive-state change, including change-and-return; each result is dropped and its buffer closed. An unchanged, shareable request may produce a frame.
- Delay callbacks across obscuration, Stop, suspend, screen-off, geometry change, detach and replacement grant; verify no frame is encoded, retained or sent and every buffer is closed. Exercise event/callback races.
- Delay an otherwise valid callback past `FRAME_MAX_AGE_MS`; verify rejection using request time even when the result timestamp is recent. Test age boundaries on the tablet clock.
- Clear the ring for each invalidation and verify both display references and input are cleared; delayed frames, acknowledgements and commands cannot restore or use the old reference.

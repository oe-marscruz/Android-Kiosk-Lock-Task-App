# G02: Attachment lifecycle

Replaces/amends: ARCHITECTURE.md v0.2 §§2.1 (limits), 2.2 (local opt-in and invalidation), 3.1 (live expiry), 3.3 (attachments and lease; attach/detach rows), 4 (message lists, frames and grant semantics), 9 (single-attachment reconciliation).

## Drop-in replacement

### Attachment and lease (§3.3)

One tablet has at most one live attachment, bound to its authenticated device connection and one staff session and socket. The relay serializes transitions, deadline checks, revocation and routing per device. `none`, `status`, `pending_approval`, `granted` and `released` are attachment states; `released` is terminal for that ID and the slot then becomes `none`. A kiosk request reserves the slot before asking for approval; it does not require a pre-existing lease or grant. Authorization and audit still precede admission. The policy table determines permitted operations in each state.

The relay mints `attachment_id` from 128 cryptographically random bits, encoded as 32 lowercase hex characters, on each acquisition. It returns the ID and state to the owning desktop; IDs are never reused. The ID is not a credential. Every attachment-scoped message is checked against the current ID, authenticated socket, device and session; stale or mismatched IDs are rejected or dropped, never applied to the current attachment. The tablet similarly matches the ID before applying a request, command or detach. A replacement gets a new ID, including a same-owner mode change, so a delayed approval or detach cannot affect it.

`LEASE_IDLE_S=60` bounds the lease from acquisition or its last authorized substantive operation or accepted `lease_renew`. The owner sends `lease_renew{device_id, attachment_id}` before expiry, including while awaiting approval. The relay checks the live binding, session, scope and deadline atomically before renewing; it returns the resulting lease deadline to the owner. Renewal does not extend local consent, the approval deadline or the staff session idle timer. Frames, pings, status, acks and denied requests renew neither lease nor session. Session absolute and idle expiry still close the socket and release the attachment. Expired leases cannot be revived by a late renewal. Each deadline uses a monotonic clock at the enforcing party.

`APPROVAL_TIMEOUT_S=60` is a positive, bounded relay configuration limit. Pending approval expires at the earlier of this deadline or lease/session expiry. The tablet also bounds its prompt and grant locally; relay renewal cannot prolong either. A grant is usable only while the attachment is `granted`, the tablet's local grant and banner are valid, and the lease and session remain live. The tablet creates the grant and enforces its own monotonic expiry; the relay cannot create or extend it.

| From | Trigger and atomic condition | To | Side effects |
|---|---|---|---|
| none | Authorized `attach{mode:"status"}`; device connected and slot free | status | Reserve slot, mint ID and start lease; return ID/state. |
| none | Authorized `attach{mode:"kiosk"}`; device connected and slot free | pending_approval | Reserve slot, mint ID, start lease and approval deadline; send `support_request` with ID and authenticated name; return ID/state. No content or input yet. |
| status | Same owner requests kiosk | pending_approval | Atomically release old ID and reserve a new ID; start fresh lease and approval deadline; send old-ID `detach`, then new-ID `support_request`. No grant carries over. |
| pending_approval or granted | Same owner requests status | status | Atomically release old ID and reserve a new ID; send old-ID `detach`, stop prompt/capture/input and clear grant and queues; start new lease and return ID/state. |
| status, pending_approval or granted | Same owner requests current mode | unchanged | Return current ID/state; no new grant or deadline extension. |
| status, pending_approval or granted | Different owner attempts attach | unchanged | Return `LEASE_BUSY`; do not interrupt owner or reset deadlines. |
| pending_approval | Matching `support_pending` before deadlines | pending_approval | Report pending to owner; no deadline extension. |
| pending_approval | Matching `support_granted` before all deadlines and after local Allow and visible banner | granted | Bind tablet grant to this ID; report grant to owner. |
| pending_approval | Denial, missing UI or approval timeout | released → none | Cancel prompt, notify owner with reason and release slot. Late replies are ignored. |
| granted | Local Stop, local grant expiry or other §2.2 invalidation | released → none | Revoke grant; stop capture/input, discard queued frames and input, notify owner and release slot. |
| status, pending_approval or granted | Owner `detach`; lease expiry; staff or device disconnect; session expiry/logout/revocation; role/scope removal; device revocation | released → none | Invalidate ID and grant, cancel prompt, discard queued work, stop capture/input, notify reachable peer with ID and reason. Dispatched commands without ack remain `OUTCOME_UNKNOWN`. |
| status, pending_approval or granted | Valid `lease_renew` before expiry | unchanged | Reset lease deadline only; return deadline. |

Transitions are committed before notifications or forwarding. Failure to deliver a request or confirm a safe transition fails closed and releases the ID. On reconnect or relay restart no attachment or grant is restored. In-flight messages and work are rechecked against the current ID and deadlines at dispatch; a stale `support_granted` cannot bind to any replacement. Tablet-side invalidation is immediate even if its notification is delayed or disconnected.

### Wire amendments (§4)

- `attach{device_id, mode}` returns the relay-minted `attachment_id` and state. Same-owner mode changes use the table above. `lease_renew{device_id, attachment_id}` returns the lease deadline.
- Carry `attachment_id` on `support_request`, `support_pending`, `support_granted`, `support_stopped`, both hops of `cmd`, binary frame headers, and both directions of `detach`. Support replies and frames are routed only for the matching current ID and state. `detach` is ID-specific and cannot release a replacement. Reconcile frame and grant fields with the frame-binding specification at schema freeze.
- `LEASE_BUSY` means another owner holds the slot; `LEASE_REQUIRED` covers absent, expired or mismatched attachment IDs. Existing grant and session errors remain applicable. The schema registry specifies response envelopes and stop reasons.

## Acceptance tests:

1. Race two authenticated attaches against one tablet: exactly one ID wins and the other receives `LEASE_BUSY`. Same-owner mode changes produce a new ID and revoke old work; repeating the current mode preserves the ID.
2. Delay an approval, switch mode or detach, attach again, then deliver the old approval, frame, command and detach. None binds to or changes the new attachment; no content or input passes without its own approval.
3. With a controlled monotonic clock, renew a passive viewer across multiple 60 s lease intervals. Verify consent expiry and staff idle expiry still stop access; renewal at or after lease expiry fails. Pending approval times out even with renewal; denial and missing UI release the slot.
4. Exercise local Stop, boundary invalidation, grant expiry, detach, both socket disconnects, session expiry, logout and revocation. Verify immediate tablet stop, queue disposal, terminal old ID, no replay after reconnect, and a new owner can attach. Test a dispatched command without acknowledgement returns `OUTCOME_UNKNOWN`.
5. Race approval, renewal, detach and expiry at their deadlines; exactly one serialized outcome wins and no expired grant or lease dispatches work. Verify a failed request delivery releases the slot.

# F01 — kiosk boundary

Replaces/amends: §§2.1, 2.2, 2.3, 3.3, 4, 5.1, 6, 8. The following text replaces the conflicting capture, input, banner and policy statements in those sections; preserve their other statements.

## Drop-in text

### §2.1 Relay configuration (add)
- `REMOTE_SUPPORT_POLICY=attended_only` is the default. `status_admin` permits unattended status and explicitly authorized non-content admin commands only; it never permits frames, remote input or navigation without local opt-in. Unknown values fail startup. The relay enforces this on every operation, not only at attach.

### §2.2 Tablet agent (replace capture, input and isolation bullets)
- Remote viewing and input target only the foreground `MainActivity` kiosk window and its WebView content area. Chrome, launcher, Wi-Fi screens, system UI, dialogs and other windows are outside the boundary. Keep `ALLOWED_DOMAINS` unchanged. The tablet independently enforces the boundary even if the relay is compromised.
- `KioskA11yService` uses `takeScreenshotOfWindow()` for the verified active kiosk window on API 34+. Never fall back to display screenshots. Secure-window errors, ambiguous window identity, obscuration, or inability to prove the boundary stop viewing and input. Screenshot capability and window retrieval must be declared. [Android AccessibilityService reference](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#takeScreenshotOfWindow(int,%20java.util.concurrent.Executor,%20android.accessibilityservice.AccessibilityService.TakeScreenshotCallback)).
- A local person explicitly approves each named staff support session on the tablet before any content capture or input. Approval is local, session- and device-bound, time-limited, revocable via a local Stop control, and cannot be granted by remote input. No auto-acceptance. No approval persists across disconnect or a new session. Denial, timeout or absence of the local UI fails closed.
- Show a native, noninteractive, non-dismissable banner in the kiosk UI with a bounded, plain-text authenticated staff display name; never interpret it as markup. The local Stop control is separate. Confirm banner visibility before capture or input, and stop both if visibility cannot be established. Do not include sensitive workflow content in frames: sensitive routes and states are blocked by an explicit tablet-side allowlist; unknown states fail closed. Local staff must leave sensitive workflows before starting support. No masking or route detection is presumed sufficient until verified on-device.
- Focus loss, obscuration, sensitive state, local Stop, approval or controller lease expiry, disconnect, service failure or banner loss immediately invalidate the grant, stop capture, discard queued frames and input, and require a fresh local approval. Recheck at capture completion and immediately before dispatch; discard results after invalidation.
- Projection streaming is disabled in v1 until it can prove the same window-only and sensitive-content boundary. OS projection consent is separate from, and never substitutes for, local support opt-in.

### §2.3 Desktop controller (amend)
- Viewer shows pending local approval and stopped reasons. Remove global HOME, RECENTS and BACK controls; offer only kiosk-scoped `kiosk_back` and `kiosk_home`, implemented within `MainActivity` and subject to the same boundary and allowlist as touch. Do not navigate outside the kiosk WebView.

### §3.3 Authorization & audit (amend)
- Roles remain necessary but do not bypass local approval or the kiosk boundary. Audit approval, denial, revocation and stop reason with session, user, device and time; never log content or raw URLs. A status-only connection is not a content session.

### §4 Wire protocol (amend)
- `attach{device_id, mode:"kiosk"}` requests support; it does not authorize capture. Relay forwards the request and authenticated bounded display name to the tablet. Tablet reports `support_pending`, `support_granted{grant_id, expires_at}`, or `support_stopped{reason}`. Relay binds the grant to the authenticated session, device and controller lease; it cannot create or extend a grant. Tablet uses a monotonic deadline; relay expiry is an additional restriction.
- Each frame carries grant ID, monotonically increasing `frame_id` and a window/geometry generation. Each input command carries those identifiers and normalized coordinates. Accept only the most recently delivered frame, within 1 second of its tablet capture, with unchanged grant, foreground window, geometry and content-area bounds. Reject stale, replayed, out-of-bounds or uncertain coordinates. Transform to screen coordinates only after validating the complete gesture path stays inside the current WebView content area; revalidate immediately before dispatch. Exclude native controls, banner and Stop control. If safe dispatch cannot be established, disable remote touch.
- Remove `key{BACK|HOME|RECENTS}`; add `kiosk_back` and `kiosk_home`. `tap`, `swipe` and `long_press` require an active grant. Status and non-content admin operations remain role- and device-authorized, independently of support approval. No content-bearing status, including raw URLs, is available unattended.

### §5.1 and §6 Screen view (replace conflicting claims)
- V1 uses only locally approved, window-scoped accessibility capture. API 34+ is required for remote view; unsupported or unverifiable devices report unavailable. No consent-free capture, whole-display fallback or projection streaming. Capture can fail for secure windows and must fail closed. Android gesture dispatch targets the touchscreen, so kiosk containment is an application-enforced condition and requires the K11 checkpoint.

### §8 Open questions (add)
- Does the Equity office approve the default attended-only policy, and should `status_admin` be enabled for specified non-content administrative operations? Which kiosk routes or states may be shared, and how will sensitive workflows be reliably identified on the tablet?

## Acceptance tests:
- Relay unit tests: default and invalid config; status-only policy; no frame, input or navigation before grant, after expiry, revocation, disconnect or wrong session/device/lease; no heartbeat extends approval. Status contains no URL or content.
- Tablet/emulator tests: deny, timeout and Stop produce no frames or input; grant requires visible banner and fresh local action; malformed or oversized staff names render as bounded plain text. Focus loss, overlay, sensitive or unknown state, window change, service failure and banner loss invalidate grant and discard in-flight capture and queued commands.
- Exercise stale, replayed, wrong-generation, expired and out-of-bounds coordinates and swipes crossing the WebView boundary; verify no dispatch. Verify kiosk navigation cannot open Chrome, Settings or launcher and preserves the domain lockdown.
- K11 checkpoint: verify local opt-in and Stop in lock task, banner visibility, window identity and screenshot contents; open Chrome, Wi-Fi, system dialogs and sensitive workflows while attached and verify immediate stop with no leaked frame or input. Test secure-window errors and focus/geometry races. If any boundary cannot be demonstrated, ship remote viewing and input disabled.

## Interfaces touched:
`REMOTE_SUPPORT_POLICY` (`attended_only`, `status_admin`); `attach` mode `kiosk`; `support_pending`, `support_granted`, `support_stopped`; `grant_id`, `expires_at`, `frame_id`, window/geometry generation; `kiosk_back`, `kiosk_home`; remove `key` and display/projection capture modes; `KioskA11yService`, `MainActivity`.

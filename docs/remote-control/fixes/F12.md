### §2.3 packaging bullet
- Packaging: CPython 3.12 x64 (pin an exact security patch in CI), PyInstaller 6.20.0, websockets 17.4, Pillow 13.0.0 and certifi 2026.10.23. Commit a Windows x64 Python 3.12 lock with exact versions and SHA-256 hashes for every direct and transitive build and runtime dependency; generate and review it from PyPI wheel metadata, then install in a clean environment with `pip install --require-hashes --only-binary=:all: -r requirements-win.lock`. CI and `package-win.sh` use this same lock and fail on drift. Refresh the lock and CA bundle through reviewed updates. Bundle certifi's `cacert.pem` with PyInstaller and use `ssl.create_default_context(cafile=certifi.where())` for every desktop HTTPS and WSS connection; retain `CERT_REQUIRED` and `check_hostname=True`. Never bypass verification or fall back silently to an unverified connection.
- Build `CU-Denver-Equity-Kiosk-Manager.exe` on Windows x64. Before any public release, CI signs the final executable with CU's trusted Authenticode code-signing identity using SHA-256 and an RFC 3161 SHA-256 timestamp, then verifies the signature and timestamp with Windows SignTool (`verify /pa /all`). Use a protected signing service or hardware-backed key where required by the CA; CI secrets `WINDOWS_SIGNING_CERTIFICATE` and `WINDOWS_SIGNING_PASSWORD` are used only if CU's approved signing mechanism supports PFX import, with `WINDOWS_TIMESTAMP_URL` configured for its TSA. Never commit keys. If CU has no certificate, CI produces an unsigned internal test artifact only; disable both rolling and tagged public publication until signing is provisioned and verified. Signing does not guarantee SmartScreen reputation: a fresh signed download can still warn or be blocked; record the outcome and work with CU IT on reputation or policy, without instructing staff to bypass warnings.

### §3.1 step 1 listener detail
Before opening the system browser, create an IPv4 TCP socket, set `SO_EXCLUSIVEADDRUSE` before binding, bind only `127.0.0.1` with port 0, listen and use the assigned port. Do not set `SO_REUSEADDR` or bind a wildcard or IPv6 address. Fail login if exclusive binding fails; close the listener on completion, cancellation or timeout. This confines the listener to the host and normally avoids an inbound Defender Firewall prompt, but managed policy and endpoint software can differ; verify on both target OSes. Exclusive binding does not authenticate local processes; retain state and handoff validation.

### §7 P6 row

Acceptance tests:
- CI installs the complete lock in a clean Windows x64 CPython 3.12 environment with hashes and binary-only enforcement; missing, altered or unlocked dependencies fail. The bundled EXE resolves certifi's CA file. A valid relay certificate succeeds for HTTPS and WSS; untrusted, expired and hostname-mismatched certificates fail.
- From fresh downloads on separate Win10 x64 and Win11 x64 machines, as standard users with no admin elevation, no Python installed and no tablet attached: check the publisher and timestamp in file properties and `signtool verify /pa /all`; record OS build, artifact hash, signature and SmartScreen/Defender results. Launch and close the app; confirm usable UI and graceful no-device/ADB behavior. Start login, complete system-browser Duo flow against staging, confirm callback and device list, then log out and repeat. Test cancellation and timeout, and confirm the port closes. No inbound firewall prompt or firewall rule change is acceptable for the release; investigate any prompt under CU policy. Verify no UAC elevation is requested.
- Inspect the listening socket during login: only IPv4 `127.0.0.1`, ephemeral port; a competing bind fails while it is held, and another machine cannot connect. Verify malformed callback/state fails and no session is granted. Record results and block release on any failed check, including a SmartScreen block preventing normal staff use.

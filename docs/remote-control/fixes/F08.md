# F08 — Accessibility and SDK

**Replaces/amends:** §§2.2 (KioskA11yService bullet), 5.1, 5.3, 5.8, 6 (screen-view row). Merge the §5.1 wording with the projection-consent fix and the kiosk-window boundary fix.

## Drop-in replacement text

### §2.2 — replace the KioskA11yService bullet; add service configuration

- `remote/KioskA11yService`: a bound AccessibilityService for kiosk-scoped gestures and window capture. On API 34+ use `takeScreenshotOfWindow()` only for the verified foreground kiosk window. Never substitute a display screenshot for remote viewing. 2–3 fps is best effort, not a guarantee.
- Declare the service with `android.permission.BIND_ACCESSIBILITY_SERVICE`, the `android.accessibilityservice.AccessibilityService` intent filter and `android.accessibilityservice` XML metadata. The metadata includes:

```xml
<accessibility-service xmlns:android="http://schemas.android.com/apk/res/android"
    android:accessibilityEventTypes="typeWindowStateChanged|typeWindowsChanged"
    android:accessibilityFeedbackType="feedbackGeneric"
    android:accessibilityFlags="flagRetrieveInteractiveWindows"
    android:canRetrieveWindowContent="true"
    android:canPerformGestures="true"
    android:canTakeScreenshot="true"
    android:notificationTimeout="100" />
```

- Report `caps.a11y` true only after `onServiceConnected`; clear it on unbind, destruction or loss of access, and publish changes on reconnect. Report window capture available only when bound and API 34+; attachment still requires the current kiosk window and all session safeguards. An enabled setting alone is not readiness.
- Handle screenshot callbacks without sending stale frames: secure window → stop capture and report `secure_window`; interval too short → drop the request and retry with bounded pacing, never busy-loop; invalid window/display → stop, re-resolve the target and revalidate the kiosk boundary before retry; no accessibility access → clear readiness; internal/unknown errors → stop and report failure with bounded retry. Close each screenshot hardware buffer after use. Display `takeScreenshot()` exists on API 30+ but is not a remote-view fallback. The AOSP 333 ms interval is a throttle, not a promised frame rate. [Android API](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService), [AOSP implementation](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/services/accessibility/java/com/android/server/accessibility/AccessibilityServiceConnection.java).

### §5.1 — replace accessibility capture sentence

Default remote view uses the foreground kiosk window via `takeScreenshotOfWindow()` on API 34+, subject to local opt-in and the kiosk boundary. It is best effort; secure windows and capture failures stop the stream. Projection requires local consent for each session; accessibility must not accept the dialog.

### §5.3 — replace

3. **Supervised enablement:** Install via a trusted installation path and verify the installed signer and service on the K11. Restricted settings and OEM behavior may affect enablement; do not assume the installation path bypasses them. During attended USB setup, read the current user's `enabled_accessibility_services`; append the exact `com.example.webkiosk/.remote.KioskA11yService` component only if absent, preserving all existing colon-separated entries, and write the merged value. Set `accessibility_enabled` to `1` if needed. Read back both settings and confirm the service actually binds. If the write or binding fails, use the supervised system settings flow, including any restricted-settings approval; fail setup if it still cannot bind. Do not silently replace other services.
   If the DPC uses `setPermittedAccessibilityServices`, first preserve the existing permitted packages and add `com.example.webkiosk`; the API takes **package names**, returns success/failure, and restricts eligibility rather than enabling a service. A null policy means unrestricted: leave it unrestricted unless a policy is explicitly required. Verify other enabled services remain permitted. [DevicePolicyManager](https://developer.android.com/reference/android/app/admin/DevicePolicyManager#setPermittedAccessibilityServices(android.content.ComponentName,%20java.util.List%3Cjava.lang.String%3E)).
   Reboot, unlock if required, and verify the settings, other services and actual binding persist. Complete enrollment and device checks, then turn off USB debugging, revoke debugging authorizations and disconnect USB. Re-enable only during supervised maintenance and retire it again afterward. If enablement or persistence fails, report unavailable and do not deploy remote control on that build.

### §5.8 — replace

8. **minSdk:** P1 keeps the existing minimum unchanged (21); Gradle migration preserves behavior. Gate `dispatchGesture` at API 24, display screenshots at API 30, and window screenshots at API 34. Below API 34, kiosk-window remote viewing is unavailable; never fall back to whole-display capture. Keystore and StrongBox are not reasons to raise minSdk to 30. Test the actual API 35 fleet.

## Acceptance tests

- Unit: merge an empty, populated and already-containing enabled-service list; preserve every other component, avoid duplicates, and handle failed read/write without reporting success. Test null and existing permitted-package policies, failed DPC result, and preservation of other packages.
- Unit: API 21/23/24/29/30/33/34/35 capability gates; readiness transitions on bind, disconnect and access failure; each screenshot error produces the stated stop/retry behavior, with no display fallback or stale frame. Verify buffers close on success and discarded frames.
- API 35 emulator: bind service and capture the foreground kiosk window; confirm a `FLAG_SECURE` window yields no frame, rapid requests handle throttle, invalid window/display errors stop and revalidate, and disabling the service clears readiness. Verify window changes and loss of focus stop capture.
- K11 checkpoint: record installation method, signer, pre-existing services and policy; perform supervised setup twice, verify no entries are lost or duplicated and the service binds. Cold reboot and unlock, verify all prior services and binding persist; disconnect USB, disable debugging and revoke authorizations, and verify remote readiness without ADB. Exercise restricted-settings and failure recovery on the fleet image; block rollout if any step fails.

# F06 — Live authorization

Replaces/amends: §§2.1, 3.1, 3.2, 3.3, 4. Replace §3.3 and §4; apply the following additions to §§2.1, 3.1 and 3.2. Enrollment and login mechanics remain subject to findings 3–5.

## §2.1 addition

- The relay is authoritative for current role, device scope, session state, attachments, leases, command admission and audit. A policy change or revocation is applied to live connections immediately. Fail closed if authoritative state or audit persistence is unavailable.

## §3.1 addition

- The 8 h absolute lifetime and 30 min idle timeout apply to open sockets as well as token use. Measure idle from the last authorized, substantive staff operation; ping/pong, frames, status, acknowledgments and denied requests do not extend it. At either expiry close the socket, release attachments and leases, and require login again. Logout and session revocation do the same immediately.

## §3.2 addition

- Device revocation atomically disables the credential and closes its socket, attachments and controller lease. Discard pending commands; explicit re-enrollment is required. Enrollment approval is authorized against the pending request and its assigned device scope, not merely a logged-in session.

## §3.3 Authorization & audit

- Map each authenticated principal to a current role and explicit device IDs or device groups in relay configuration. No mapping or empty scope grants no access. Roles are cumulative: admin includes operator; operator includes viewer. Scope is checked for each operation and again immediately before forwarding a queued command. A role or scope removal immediately ends affected attachments and leases and discards their queued commands. Reauthentication does not restore an attachment automatically.

| Operation | Minimum role | Device scope and additional condition |
|---|---|---|
| `list_devices` | viewer | Return only devices in scope; do not disclose others. |
| `attach`, view frames/status, `detach` | viewer | Target in scope; attachment bound to this session and socket. |
| Acquire/release control; `tap`, `swipe`, `long_press`, `key` | operator | Target in scope; active attachment and controller lease. Only kiosk-scoped input is permitted. |
| `reload_kiosk` | operator | Target in scope; active attachment and controller lease. |
| `set_url` | admin | Target in scope; active attachment and controller lease; destination validation on tablet preserves `ALLOWED_DOMAINS` (see finding 2). |
| `lock_now`, `reboot`, `enter_kiosk` | admin | Target in scope; active attachment and controller lease. |
| `exit_kiosk`, `wipe` | admin | Target in scope; active attachment and controller lease; desktop confirmation and single-use step-up grant bound to principal, session, device and action. Disabled until fresh MFA evidence is verified (finding 5). |
| Approve enrollment | admin | Pending request assigned to a device in scope; physical fingerprint verification and proof of possession (finding 3). |
| Read audit | admin | Return only events for devices in scope; events without a device require explicitly configured audit-wide scope. |
| Revoke device | admin | Target in scope. |
| Revoke staff session | admin | Only sessions whose entire device scope is within the admin's scope; self-logout is always allowed. |

- Any number of authorized viewers may attach within capacity. At most one attachment holds a controller lease per tablet. Acquisition is atomic; a competing request fails explicitly. The lease is bound to the session, socket, attachment and device; it expires after 60 s without an authorized control operation, or immediately on detach, disconnect, session expiry, logout, revocation, role/scope removal or device disconnect. A viewer may request control again after release; no automatic transfer. Capture and input stop when their required attachment or lease ends, consistent with finding 1.
- Append audit events for session and attachment starts/ends, lease grants/denials/releases, enrollment approval, revocations, authorization denials, destructive intent and command outcomes. Each event has a server-generated event ID, UTC timestamp, principal `(iss, sub)` when known, session ID (non-secret identifier), device ID when applicable, operation, decision, reason code, command ID when applicable, and outcome. Record destructive intent before dispatch and outcome separately. Only relay code writes the append-only log; authorized reads are scoped as above. Never log tokens, codes, credentials, signatures, raw URLs, command arguments, frame data, screenshots or student content.

## §4 Wire protocol (v1)

WSS, JSON control messages and binary frames. JSON messages have `{"v":1,"type":...,"id":...}`. Device messages are `hello{device_id, sig, app_version, caps}`, binary `frame`, `ack{id, ok, err}` and `status{lock_task, url, battery, wifi}`. Staff messages are `list_devices`, `attach{device_id, mode}`, `detach`, control lease acquire/release, and `cmd{device_id, op, args}`. The command allowlist is `tap`, `swipe`, `long_press`, `key`, `reload_kiosk`, `set_url`, `lock_now`, `reboot`, `exit_kiosk`, `enter_kiosk`, `wipe`; kiosk boundary and destination rules in findings 1–2 further restrict these operations.

- A command ID is unique per session and retained with its outcome for the session lifetime, including reconnects. Atomically reserve it before admission. A duplicate is never dispatched again; return its recorded outcome, or a pending indication if unresolved. A reused ID with different content is rejected. Bound retained IDs per session; when full, reject new commands until a new session is established. Never evict IDs within the replay window (the entire session lifetime).
- Each command has a relay-set deadline of 5 s from admission. Use bounded per-device queues (32 commands) and a 20 commands/s per-session rate limit. Reject full queues or rate-limit excess explicitly; never silently drop an admitted command. Expired commands are rejected before dispatch. Drop frames under backpressure. On disconnect, lease loss or device reconnect, fail and discard queued commands; do not replay them. A dispatched command with no acknowledgment by its deadline has an unknown outcome, not a success or an automatic retry. The tablet deduplicates command IDs for the current connection and rejects expired commands before execution.
- Return explicit errors: `FORBIDDEN`, `SESSION_EXPIRED`, `LEASE_BUSY`, `LEASE_REQUIRED`, `OVERLOADED`, `DEADLINE_EXCEEDED`, `DUPLICATE_ID_CONFLICT`, `OUTCOME_UNKNOWN`, and `DISCONNECTED`. Reconnect requires fresh authentication or device challenge as applicable, a new attachment and an explicit lease acquisition; no queued command or previous lease survives. Device acknowledgments correlate to the original command ID.

## Acceptance tests:

- Parameterize every matrix row across roles, in-scope and out-of-scope devices; assert allowed results and `FORBIDDEN`, and assert list/audit responses contain no out-of-scope records. Test enrollment fingerprint mismatch and unverified step-up deny without dispatch.
- With two staff sockets, race lease acquisition for one tablet: exactly one succeeds; viewers still attach. Verify every control operation without the winning lease fails, and release, expiry and disconnect permit a new acquisition.
- With a fake clock, hold a socket open with ping/pong, frames and denied operations: idle expiry closes it at 30 min; authorized activity cannot extend the 8 h absolute expiry. Logout, session/device revocation and role or scope removal close or detach immediately and prevent further dispatch.
- Send duplicate IDs concurrently and after reconnect: exactly one tablet dispatch occurs; same payload returns pending/result, changed payload returns conflict. Fill the retained-ID limit and verify explicit rejection without eviction.
- Block a fake tablet, fill the queue and exceed the rate limit; assert explicit overload, deadline failures and no late execution. Disconnect or revoke with queued commands and assert none replay on reconnect. Lose an acknowledgment after dispatch and assert unknown outcome without retry.
- Inspect persisted audit records for grant, denial, destructive intent and outcome with correlation fields; assert no secret, raw URL, arguments or frame bytes are present. Simulate audit-store failure and assert privileged action is not dispatched.

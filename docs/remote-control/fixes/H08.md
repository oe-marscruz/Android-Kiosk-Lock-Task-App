### §7: P1b and ordering

P1b must merge and its matrix pass before **any remote implementation** merges, including `relay/` alone in P2, P3 desktop/relay code and P4 Android code. P1a may draft fixtures before then. P3i and P3k each precede P4; K11 failures disable the affected path.

### §7.2: Publication gate (P1b)
- **Classification.** Each candidate has capability (`usb-only` or `remote-capable`), APK (`release` or `debug`), and on Windows exe (`authenticode-signed` or `unsigned`). `REMOTE_FEATURES` must be exactly `0` or `1`. Inspect checkout and package contents against a maintained inventory: `relay/`, `kiosk_remote/` or remote Android code makes it remote-capable, even if disabled or unbundled. Flag mismatch, unknown layout or invalid classification fails closed.
- **Verification.** Independently verify the APK signature and signer with `apksigner verify --print-certs`, and compare its hash, variant and signer to `apk-info.txt`; release also needs the approved fingerprint. Never relabel debug as release. Extract the APK without execution from **every final EXE**, after signing if signed, using a pinned PyInstaller extractor. Require exactly the expected APK and matching hash and signer, including for the unsigned USB-debug exception. Mount the final DMG read-only and verify every expected APK copy; missing, extra, stale or unverifiable copies fail. Record commit, class, package and APK digests, fingerprints and results.
- **Windows signing.** Sign with SHA-256 and RFC 3161 (`/tr` and `/td SHA256`). Verify the final EXE with `signtool verify /pa /all /tw`; require a valid RFC 3161 timestamp token for each signature, independently inspect its type if necessary, and retain evidence bound to the EXE digest. `/tw` warns when a timestamp is absent; it alone does not distinguish timestamp protocols. Fail on any SignTool warning or error, including warnings returned with exit code zero, and on absent, invalid or non-RFC 3161 timestamps. Never fall back to unsigned after signing failure.
- **Matrix.** All checks precede any upload or release mutation. Failed checks leave existing releases untouched.
  - **Windows default-branch push:** USB-only debug + unsigned may be uploaded only as `windows-usb-debug-unsigned-internal` to Actions in a private repository with access restricted to authorized testers. It is not a public release. USB-only release + signed may publish a labelled prerelease. Remote-capable candidates never update `latest`; all other combinations publish nothing.
  - **Windows `v*` tag push:** only release APK + verified signed EXE may publish; label capability and signing status. Remote-capable also requires P0, P5b, §5.7, fleet-upgrade and §7.3 evidence tied to the commit and package digest. Debug or unsigned publishes nothing.
  - **macOS:** only restricted private-repository Actions artifacts: `macos-usb-debug-internal`, `macos-usb-release-internal`, or `macos-remote-release-internal`; remote debug publishes nothing. No public DMG release.
  - **`workflow_dispatch`:** manual runs never create or modify releases or upload distribution artifacts, regardless of ref or inputs. They may run build and verification checks without publication.
  - **PR:** no release secrets or write permission. Never test secrets directly in `if:`; check them through environment variables or steps without logging values.
- **Distribution and legacy link.** A public-repository prerelease is public; Actions artifacts are downloadable by users with repository read access, which is not an internal restriction on a public repository. Until a private authorized destination exists, upload no internal debug artifact. As a planned P1b cutover, remove the legacy `CU-Denver-Equity-Kiosk-Manager.exe` asset from public `latest` and remove or update the README badge, direct-download link and release instructions to point to the authorized private artifact procedure; do not rename it as a public debug asset. This retirement is distinct from a failed candidate, which must not mutate releases. Past downloads and mirrors cannot be recalled. Do not claim a working public direct download until an eligible signed asset and its actual URL exist.

### §7.3: Windows signature evidence
- On both acceptance images, verify the downloaded candidate with `signtool verify /pa /all /tw`, reject all warnings and errors, and record proof of the valid RFC 3161 timestamp and candidate hash. Keep the other §7.3 tests.

### §8.2: Fleet signing
- Inventory the deployed signers under §7.1. Until a stable signer and signed distribution exist, the USB-only debug/unsigned build is for authorized internal testing only, via the restricted destination in §7.2. Display with it: **Debug APK, unsigned executable, not a fleet release. Each CI run may use a different signing key, so updates to existing installations can fail. Do not uninstall or reset to force an update. Inventory the installed signer and follow supervised recovery.** Retire the exception once stable signing and signed distribution exist.

## Acceptance tests:
- Exercise capability × APK × EXE signature combinations for default-branch push, `v*` push, PR and manual dispatch on both workflows. Manual runs never publish even on a branch or tag ref; gate failures preserve existing releases. Verify P2 `relay/` cannot merge before P1b.
- In signed and unsigned final EXEs, substitute, omit, duplicate or stale the embedded APK; each fails before upload. Repeat for all DMG copies. Verify valid final packages against recorded hashes and signers.
- Test absent, invalid and legacy non-RFC 3161 timestamps, invalid signatures and a simulated SignTool warning with exit code zero; all fail. A correctly signed and RFC 3161-timestamped candidate passes and retains evidence bound to its digest.
- Verify debug artifacts are unavailable from the public repository; private artifact access is limited to authorized readers. Exercise cutover against a test release: remove the old asset, update both README links and instructions, and confirm no stale public debug URL is advertised. Check warnings accompany the private artifact.
- Confirm remote tag publication fails without each candidate-bound gate and that eligible paths publish only after all checks.

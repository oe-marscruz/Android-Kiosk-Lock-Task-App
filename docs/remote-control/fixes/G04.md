## Drop-in replacement Markdown

### §2.1 — Security and routing contract

`StaffSession` is an identity reference, never a cached grant. `authorize` resolves the current session, expiry, principal mapping, role, scope and policy on every dispatch. Group-based mappings use current authoritative membership; if current membership or policy cannot be established, deny. Policy updates are atomically published and ordered with dispatch; no stale per-session grant is authoritative.

```python
@dataclass(frozen=True)
class StaffSession:
    session_id: str
    principal: Principal
    display_name: str
    expires_at: datetime

class SecurityServices(Protocol):
    async def authenticate_staff(self, token: str) -> StaffSession: ...
    async def start_device_challenge(self, device_id: str, socket_id: str) -> tuple[str, str]: ...
    async def verify_device_proof(self, device_id: str, socket_id: str, sig: bytes) -> DeviceIdentity: ...
    async def authorize(self, session_id: str, device_id: str | None, op: str) -> Decision: ...
    async def consume_step_up(self, session_id: str, device_id: str, op: str, grant_id: str) -> Decision: ...
    async def revoke_session(self, session_id: str) -> None: ...
    async def revoke_device(self, device_id: str) -> None: ...
    async def audit(self, event: AuditEvent) -> None: ...

class ConnectionCloser(Protocol):
    async def close_session(self, session_id: str) -> None: ...
    async def close_device(self, device_id: str) -> None: ...
```

Retain the other §2.1 data types; `Grant` is a current policy result, not a session field. P2 owns authoritative state and P3 owns routing. They share an ordering mechanism: policy/session mutations, device revocation, attachment invalidation and final authorization plus enqueue-to-device forwarding are serialized for the affected device. Global/session changes coordinate with all affected device locks in deterministic order. Audit the privileged intent before forwarding inside that ordering; audit failure denies dispatch. If revocation or scope removal wins the ordering, no subsequent command or frame is forwarded under the removed authority; if forwarding wins, already forwarded work cannot be recalled. Purge queued work and close affected sockets/attachments before reporting mutation success. Persistent revocation remains effective if closure fails; report failure and retry cleanup. Recheck before forwarding each queued item, and fail closed if current state or audit is unavailable. Idle expiry and session invalidation use the same ordering. Tablet-side grant and boundary checks remain mandatory.

### §§3.2–3.3 — Scope and HTTP API

All JSON objects reject duplicate and unknown fields. IDs are opaque strings; timestamps are UTC RFC 3339. Administrative routes require `Authorization: Bearer <session token>` over HTTPS and current authorization at execution, never a query token. Responses use `Cache-Control: no-store`. Errors are `{"error":{"code":"..."}}`; no secrets or stack traces. `400 INVALID_REQUEST`, `401 UNAUTHENTICATED` (missing, invalid or expired session), `403 FORBIDDEN`, `404 NOT_FOUND`, `409 CONFLICT`, `410 EXPIRED`, `429 RATE_LIMITED`, and `503 UNAVAILABLE` apply as appropriate. Unknown/out-of-scope targets return `404` without disclosing them; denied operations are audited. Mutations fail closed on audit failure. Pagination uses opaque, bounded, integrity-protected cursors bound to the caller and filters; each page rechecks live authorization. No cursor grants access by itself.

A managed group is a configured scope identifier in `ACCESS_MAP`; a device belongs to exactly one group. Scope is group membership, resolved to current device IDs, rather than a static list of generated IDs. A pending request is initially unassigned. An authenticated admin can list pending requests for supervised comparison, including unassigned requests, but sees only request ID, generated device ID, fingerprint, reported key security level and expiry. This limited pre-assignment view contains no student content. The admin assigns a group they currently administer before approval; no arbitrary group creation or scope escalation is allowed. Approval atomically rechecks assignment, admin scope, pending state, expiry and submitted fingerprint. A software key requires explicit confirmation. Assignment and approval are audited. Reassignment of an approved/active device requires authority over both old and new groups and immediately invalidates affected attachments under the ordering above; revoked devices cannot be reassigned.

| Method and route | Auth; request JSON | Success JSON |
|---|---|---|
| `POST /enroll/requests` | Unauthenticated supervised tablet; `{spki_der_b64, security_level}` (`strongbox`, `tee`, `software`, or `unknown`; self-reported). Validate P-256, cap and rate-limit. | `201 {request_id, device_id, fingerprint, expires_at}`; both IDs random 128-bit lowercase hex; pending for 10 minutes. |
| `GET /enroll/requests?cursor=...&limit=...` | Admin; no body; pending only. Limit bounded by server. | `200 {items:[{request_id, device_id, fingerprint, security_level, group_id:null|string, expires_at}], next_cursor:null|string}`; assigned requests visible only in scope. |
| `PUT /devices/<device_id>/scope` | Admin; `{group_id}`; pending or non-revoked managed device, with rules above. | `200 {device_id, group_id}`. |
| `POST /enroll/requests/<request_id>/approve` | Admin; `{fingerprint, accept_software:boolean}`; compare full fingerprint physically. | `200 {request_id, device_id, group_id, state:"approved"}`. Approval does not activate; proof within original TTL does. |
| `POST /enroll/requests/<request_id>/reject` | Admin; `{}`; assigned request in scope, or unassigned pending request. | `200 {request_id, state:"rejected"}`; terminal, cannot be approved. |
| `GET /audit?cursor=...&limit=...` | Admin; no body. Filter events by current device scope; device-less events require `audit_wide`. | `200 {items:[{event_id, occurred_at, principal:null|{issuer,subject}, session_id:null|string, device_id:null|string, op, decision, reason:null|string, command_id:null|string, outcome:null|string}], next_cursor:null|string}`. Stable event ordering; no sensitive payloads. |
| `POST /devices/<device_id>/revoke` | In-scope admin; `{}`. | `200 {device_id, state:"revoked"}` after durable tombstone and cleanup. |
| `POST /sessions/<session_id>/revoke` | Admin; `{}`; target's entire current scope must be within admin's; deny if target scope cannot be established. | `200 {session_id, state:"revoked"}` after durable invalidation and cleanup. |
| `POST /auth/logout` | Authenticated session; `{}`; self only. | `200 {state:"logged_out"}` after invalidation and cleanup. |

Repeated revoke/logout is safe and never restores access; an already invalid bearer receives `401`. Pending expiry is terminal. Enrollment rejection, approval and scope updates return `409` for incompatible state or fingerprint mismatch, and `410` for expired pending requests. Routes and query keys above are the complete management surface; §3.1 login and G05 step-up routes remain separate.

### §4 — Authentication and responses

WSS upgrades start unauthenticated. Within 10 seconds the staff client sends `{"v":1,"type":"staff_auth","id":"<request-id>","token":"<session token>"}` as its first and only pre-auth application message. This works with the desktop client without credential-bearing URLs, keeps credentials out of proxy request logs, and allows a uniform application-level reply; TLS is mandatory. Redact message bodies and authorization headers in both Caddy and app logs. Reject other pre-auth messages, malformed or expired tokens, and timeout with a generic error and close; cap message size and rate. On success reply `staff_ready{session_id, display_name, expires_at}` correlated to the auth ID. The token is never echoed. Device proof success replies `device_ready{device_id}` correlated to the proof ID before `hello`; proof failure emits generic `DEVICE_AUTH_FAILED` and closes. Challenge remains socket-bound and single-use.

All control messages use the §4 v1 envelope; replies echo the request `id`, unsolicited events use `id:null`. Relay → staff messages are:

- `staff_ready{session_id, display_name, expires_at}`; `devices{items:[{device_id, state, caps}], next_cursor}` for `list_devices`, filtered by current scope; state is online, offline or maintenance, with content-free capabilities only.
- `attach_result{device_id, attachment_id, mode, state}` and `detach_result{device_id, attachment_id}`; `lease_renew_result{device_id, attachment_id, expires_at}`. G02 defines valid states, transitions and deadlines.
- `support_pending{device_id, attachment_id}`, `support_granted{device_id, attachment_id, grant_id, expires_at}`, `support_stopped{device_id, attachment_id, reason}`, and `attachment_ended{device_id, attachment_id, reason}`; stale attachment events are discarded.
- `device_status{device_id, state, caps}` and `device_disconnected{device_id}` for in-scope devices; `cmd_result{device_id, attachment_id, command_id, state, error:null|{code}}` reports pending, success, failure or outcome unknown. A result does not imply a destructive action completed.
- Binary `frame` with G03's attachment, grant, frame and generation binding; `error{error:{code}}` for rejected requests or connection errors. No frames or events after authorization removal; `session_ended{reason}` may precede close but is not guaranteed. HTTP logout is canonical; WSS `logout` has `logout_result{state:"logged_out"}` then closes, subject to the same ordering.

The P1a registry fixes field types, allowed reason/error codes, bounded sizes, request correlation, retry and close behavior, and fixtures for every message above and G02/G03 additions. Unknown versions, types, fields and codes fail closed; never echo secrets, raw URLs, command arguments or frames in errors or logs.
